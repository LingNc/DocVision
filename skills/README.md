# DocVision Skills —— Agent 驱动的书籍转换技能包

> 愿景：用户装上这个 skill，把自己的 PDF 交给自己的 agent（任何带工作区和工具调用的通用 agent），**不需要配置任何 LLM API**（除 MinerU 外零配置），对话式地完成"扫描版书籍 → 结构化 Markdown → 全书 LaTeX/矢量图重绘"的完整转换；可以随时中断，随时无损续上。

本目录是新架构（下称 **skills 线**，规划条目 P81）的开发区。旧架构（`go/`，自带会话运行时）继续作为稳定线存在，skills 线在 `skills/` 内独立演化，不侵入旧代码；两线的确定性算法资产逐步向本目录迁移。

| `docs/02-task-protocol.md` | 任务协议总表：五类任务（classify/作图/转换/核对/回炉）× 说明书 × 验收 spec |

| `agent/` | skill 侧内容：冷启动仪式 + 五类任务工作手册（classify/draw/convert/check/rework，给宿主 agent 的"怎么把活干好"） |

## 愿景

**"放下 PDF 跑到底，中途随时停，停了随便续，换个 agent 也能续。"**

- 新手用户的全部操作：把 PDF 放进目录，对 agent 说"开始"；之后只看进度通知和最终产物，全程零配置、零干预。
- 进阶用户保留全部干预口：暂停 / 看进度 / 终止归档 / 指定单章重跑 / 换书。
- agent 不持有任何进度状态。一切状态住在磁盘制品层；agent 的上下文只是磁盘状态的瞬时投影。

## 目标（设计目标，非版本承诺）

1. **LLM 会话外迁**：LLM 工作全部由宿主 agent 完成；skills 内核不发起任何 LLM API 请求（MinerU 等本地/第三方工具链调用除外）。
2. **判据代码化**：旧架构提示词中的全部"必须/不得/低于就退回"迁入 kernel 验收 spec，机械执行，不依赖 agent 自律。
3. **知识说明书化**：旧架构提示词中的方法/知识类内容（转换规则、作图规范、工具用法）抽为 per-task 工作说明书，claim 时按需下发。
4. **状态可重建**：任何时刻，全局进度可以从制品层（产物文件 + sha256）确定性重建；`progress.json` 降级为缓存。
5. **无损续接**：agent 会话压缩、关闭、换平台、换模型，冷启动仪式（`status --agent` 蒸馏视图 + 任务包）即可无损续上。
6. **多书并存**：项目注册表管理每本书的生命周期（active/paused/archived），每本书有独立 `profile.md` 知识档案，随运行积累、跨会话存活。
7. **记忆泡泡**：每个任务有独立沙箱（inputs/scratch/notes.md/out），切换任务即换指针；重入 O(1)（notes.md 两行交接语）。
8. **校验双模式**：平台支持子智能体 → 核对待开异上下文；不支持 → 延迟批量核对 + 回炉队列落盘。

## 最终验收标准

验收对象 = 一条全新流水线：**全新环境，只装本 skill + MinerU + TeX 工具链，不配置任何 LLM API，agent 为空上下文启动。**

| # | 验收项 | 通过标准 |
| --- | --- | --- |
| A1 | 端到端转换 | 一本此前未处理过的扫描版书籍 PDF，从放入到产出 `out/book.pdf` + standalone.tex，全流程完成，LLM 工作全部由宿主 agent 完成 |
| A2 | 冷启动续接 | 处理中途杀掉 agent 进程/新建空白会话 ≥3 次，每次用 `status --agent` 蒸馏视图 + claim 恢复，无任务重复执行、无任务丢失、无产物损坏 |
| A3 | 上下文压缩免疫 | 人为对 agent 会话做深度压缩（或开全新会话接管），续跑结果与未压缩对照组产物逐字节一致（除时间戳类元数据） |
| A4 | 验收不被绕过 | 故意让 agent 提交缺内容的章节 / 指向临时路径的 `\input` / 未编译产物，kernel 全部打回且不记 done；伪造与绕过尝试不改变磁盘状态 |
| A5 | 单章重跑 | 任一章人工判定不合格后走 rework 队列重跑，只影响该章及其上游整合，其余章节产物不被触碰 |
| A6 | 多书切换 | 两本书交替 active/paused ≥2 轮，各自断点独立、书级 profile.md 各自累积、互不污染 |
| A7 | 批量吞吐 | 100+ 张插图的 classify/作图阶段，批量接口（claim n / submit batch）将工具往返次数控制在任务数的 1/n 量级；单任务上下文不因历史任务膨胀 |
| A8 | 延迟核对 | 无子智能体平台上，转换-核对解耦跑完全程：核对问题全部经 rework 队列落盘回炉，无"靠 agent 记住回炉指令"的环节 |
| A9 | 判据回归 | 旧架构已固化的判据（覆盖率 ≥85%、提交门禁、dedupe 居中重合度门槛、代表图跟随等）在本线有对应验收测试，全部绿 |
| A10 | 新手零配置 | 新用户按 README 步骤（装 skill、配 MinerU、放 PDF、说"开始"）完成一本书，期间无需编辑任何配置文件 |

## 开发约定

- 内核语言 Go（与旧线一致，保住测试资产）；agent 侧内容（说明书、脚本）不限语言。
- 旧线的**判据**迁入时逐条抽取、逐字校对，不凭记忆重写（同仓库提示词维护规矩）。
- 本目录不写入任何真实样本的身份信息（书名/路径/哈希/内容描述），只写抽象计数与统计。
- 每批改动按仓库 RULE.md 的提交格式（`feat: 中文描述...`），收尾按 AGENTS.md 批次清单同步 plan/issue/CHANGELOG。
