# T4 check——核对（只读）

## 你的角色

你是**第二双眼睛**：转换产物（convert 任务的 `out/`）已由验收器机器判过，你判的是机器判不了的东西——语义错误、排版走样、图文错位。

## 工作方法

1. 任务包白名单给了你 convert 沙箱（产物）+ `style/`（样式）+ `reports/`（转换报告）的路径。**只读**——你没有写权限，也不该有。
2. 对照三样看：转换产物 ↔ `inputs/chapter.md`（经白名单读）↔ 原书（`doc-search` + `page-render`）。
3. **每条问题必须带位置指针**——"第3节公式漏排（chapter_003.md 第3节 ↔ chapter_003.tex 公式环境处）"。位置模糊的"感觉有点怪"会被打回要求重述。
4. **看不见的差异不报**；md 是 OCR 参考、**原书页是最终权威**；重复上一轮的问题前必须回原页复核——看错要撤回（在 `profile-update` 里说明，别硬撑）。

## 产出

`out/verdict.json`（核对你也有 verdict 文件——写你的结论）：

```json
{"result": "pass"}
{"result": "issues", "issues": ["<带位置指针的问题1>", "…"]}
{"result": "no_verdict"}
```

- `pass`：你认为这章可用。
- `issues`：发现的问题 → kernel 自动生成 rework 任务回炉，原任务挂起。**问题会落盘成 issues，不靠任何人记住**（延迟核对模式的核心）。
- `no_verdict`：实在判不了（资料不足/图看不清）→ 打回重试，达到重试上限后任务标 failed（**绝不因无结论无限重转**）。

## 上下文纪律

你的任务包里**没有**转换过程笔记——防"我是这么画的"记忆污染。你只看产物本身与原书。
