# 从「扫描书」到「任意 PDF」：现状盘点、技术判定与落地路线

对应条目：`docs/plan.md` 的 P68–P76（P68 为上一轮讨论遗留的待裁决项，与本报告无耦合）。
本报告只做分析与设计，不含待实施代码。

---

## 0. 一句话结论

方向正确，而且它推翻的不是"几个开关"，是流水线的三个隐含假设：**图必须重画**、**阶段顺序固定（图先于样式）**、**重试粒度只能是章**。
三处需要修正的技术判断：① 原生矢量图不需要"先重画再比对裁剪"，原页本身就能直接裁；② "扫描还是原生"不该交给会话逐页判，五条确定性信号能定型绝大多数页；③ 样式与作图的重叠是**顺序**问题，不是职责问题。

---

## 1. 现状盘点：今天的流水线假设了什么

| 今天的假设 | 代码位置 | 对原生 PDF 的后果 |
|---|---|---|
| 图片一律先分类，`vector` 就重画 | `go/internal/latex/classify.go`（`ClassText/ClassTable/ClassVector/ClassRaster`，**每张一次模型请求**） | 原生图被当成"待重画"，最清晰的原件反而被降质 |
| 作图会话只看 MinerU 裁剪图 | `go/internal/prompts/templates/latex_figure.user.md`（"Redraw the attached image as TikZ"）+ `book.go:2804`（`kindTikz` 的挂载表**只有 `work:`**） | 会话看不到原页，也拿不到矢量源；只能照着位图猜 |
| 重复图靠"内容级重复"合并 | `motif_dedupe.go:1358`（同组共享 `figures/motif_<hash8>.tex`，`SharedTex` 写进 `progress_items`） | 只解决"一模一样"，不解决"同模板、不同数据" |
| 阶段顺序：images → style → chapters | `book.go` 的阶段序列 | 模板得先定义，而样式在图之后 → 先画一遍、样式阶段再改一遍 |
| 重试/返工粒度 = 章 | `retryq`、`forceCheckerRetry`、`work/attempts/<章>` | 一张图画坏了只能整章重转 |
| 外部素材无入口 | — | 人已经有的精确图只能事后手工塞 |

实测（某项目，89 处图片引用）：`vector` 54、`text` 22、`raster` 13，其中 5 张跟随并组。也就是说这本书**付出了 54 次作图会话**；若把其中"同一模板、不同文字"的句式结构图抽成 3–5 个参数化宏，重绘次数会掉到个位数量级。

## 2. 事实：原生 PDF 里到底有什么

### 2.1 三类源文件，不是两类

| 类别 | 特征（确定性信号） | 实测样例 |
|---|---|---|
| 整页扫描 | 每页恰好 1 张整页位图、**1bpc/JBIG2/CCITT** 二值编码、几乎无字体、文本量≈0 | 每页 1888×2720 灰度 1bpc JBIG2（228 ppi）；字体 1；前 3 页文本 3 字节 |
| 整页位图 + 真文字层 | 每页 1 张整页位图，但**字体多、文本量大**（导出器把整页渲染成图又保留文字层） | 每页 2480×3508 RGB JPEG（299 ppi）；字体 9；前 3 页文本 1809 字节 |
| 原生排版 | 页内没有整页位图；字体多；文本密集；图形是 content stream 里的线框/路径 | 未取到纯样例（判断逻辑按上两行的信号反推） |

第二类是最容易被"整本判"误伤的：它每页也有一张整页图，但页面里有真正可提取的文字与矢量路径。这正是"必须逐页/逐图判"的实证理由。

### 2.2 每类能取到什么

| 手段 | 拿到的东西 | 保真 | 成本 |
|---|---|---|---|
| `\includegraphics[page=N, trim=…, clip]{原书.pdf}` | 原页某一块（**矢量**，含其字体与线宽） | 100% | ≈0 token |
| `pdfimages -all` | 页内嵌位图**原始像素**（无损，不做重采样） | 100% | ≈0 token |
| content stream 提取（`mutool`/`qpdf`） | 图形对象的路径/线框，可改造 | 高 | 中（要写 Go） |
| 重绘成 TikZ | 可套模板、可改配色/文字、体积小 | 有失真风险 | 一次会话（数万 token 量级） |

关键结论：**"原页裁切"是第三档里最便宜、最高保真的一档，应排第一优先**；重绘只在三种场景有净收益——① 图上要改字/配色/语言；② 同一模板大量复用（重绘成宏才省 token）；③ 图里有本该成为正文的部分（题注、表头）。

### 2.3 边界与坑（必须在实现里处理）

- **裁切带过来的是"字形的图"，不是可排版的文字**。图区若含关键文字且这些文字也要进正文，正文仍须转写；两者别重复（裁切时要精确到图形区，避开正文块）。
- **trim 的坐标系**：`MediaBox`/`CropBox` 不一致、页面旋转（`/Rotate 90`）、非零原点，都会让 trim 偏移。实现必须先读页框再换算。
- **体积**：整页矢量裁切可能比 PNG 大（重复嵌入字体/资源）；一份书里同一页被裁多次时，应按页去重（同一页只嵌一次，多处用 `\includegraphics` 同页不同 trim，PDF 资源里自然会合并）。
- **透明与混合模式**：裁切是"整页渲染"的语义，透明合成结果与原页一致，不会错；但要小心页面底纹（水印）被一起带进来。
- **与 MinerU 的页码映射**：`source:` 视图已经按 part 暴露原 PDF（`<part>/*_origin.pdf`，回退 `split_dir`），页码映射由 `list_source_pages` / `doc_search` 负责——裁切功能可以直接复用这条既有映射，不需要新索引。

## 3. 判定层（P70）

### 3.1 五条信号与决策表

每页先跑本机体检（全部无模型）：

1. `pdfimages -list`：这一页有几张内嵌图、像素尺寸、位深、编码；
2. 图占页面比例（按像素/页面尺寸换算 ppi 与面积比）；
3. `pdffonts`：页内字体数与是否嵌入；
4. `pdftotext -f N -l N`：文本字节数；
5. 是否"整页只有一张图"（图面积 ≥ 页面 90%）。

| 内嵌整页图 | 字体 | 文本 | 判定 | 取图档位 |
|---|---|---|---|---|
| 是（二值/低 bpc） | ≈0 | ≈0 | 整页扫描 | 走 OCR 复原（现状） |
| 是（高质量 RGB/JPEG） | 多 | 多 | 整页位图 + 文字层 | 文字用文本层、**图区裁切原页** |
| 否 | 多 | 多 | 原生排版 | 图区裁切原页 / 提取内嵌图 |
| 否 | 少 | 少 | 可疑（损坏或特殊） | 交会话裁定 |

只有最后一行与"页内既有文字又有复杂矢量"的页才进会话，预计 <10%。这一条同时把 `classify` 的调用量压下来（见 3.3）。

### 3.2 落盘

- `source/audit/pages.json`：每页一条（part、页号、内嵌图清单、字体数、文本量、判定、置信度）；
- `progress_items` 每张图增两个字段：`origin`（`scan`/`embedded`/`vector`/`mixed`）、`crop`（来源 part、页号、bbox、页面旋转）；
- 这是**派生产物**，真源仍是 `progress_items`（与 `source/dedupe/groups.json` 同一规矩：可复查、可当续跑凭证）。

### 3.3 与 classify / dedupe 的关系

- `origin` 先定；`classify` 之后只回答一个问题："这个图形值不值得重画"（而不是"它是什么"）。预计 classify 请求减少 50–80%（原生 PDF 上绝大多数页有确定性结论）。
- `dedupe` 前置一步按 `sha256` 收缩：原生 PDF 里同一张图重复出现极常见（页眉、图标、同一模板图），字节相同就是同一份资产，不必进核验会话，也不必重画。

## 4. 三档取图（P69）

### 4.1 决策与资产层

`figure_action ∈ {crop, extract, redraw, skip}`，按图定，落进 `progress_items`。
**md 占位符不动**：`![](images/<book>/<file>)` 这条引用是全书唯一锚点，换的只是它背后的资产（`source/images/<书>/<file>` 那套铺图 + 自愈逻辑照用），章节转换读到的仍是同一个路径。

- `crop`：生成 `figures/<name>.tex`，内容是 `\includegraphics[page=<N>, trim=<l b r t>, clip]{<part>.pdf}`（该 PDF 由 `source:` 视图提供，或复制一份进 `source/figures/`）；
- `extract`：资产就是原图字节（`pdfimages -all` 直接落盘），章节 `\includegraphics{images/...}`；
- `redraw`：走现有作图会话（模板化见第 5 节）；
- `skip`：已在 md 里作为文本/fence 表达，不需要图。

### 4.2 提交校验（checker 侧）

| action | 必须落地的东西 | 校验方式 |
|---|---|---|
| crop | 页码 + trim + 来源哈希 | 解析 `\includegraphics[page,trim,clip]`，核对页号存在、trim 在页框内 |
| extract | 文件哈希 + 来源对象号 | 与 `pdfimages` 清单对账 |
| redraw | `figure.tex` + 编译产物 | 现状（compile + compare_figure） |

## 5. 重复结构 → 模板（P71）

### 5.1 现状的边界

`motif_dedupe` + `figures/motif_*.tex` 解决的是"内容近似相同"（居中重合度判据）。模板族（同结构、不同文字/数据）不在其内，所以 54 张里同一套句式结构图仍是 54 次绘制。

### 5.2 两步走

1. **结构聚类**：在"去掉文字后的骨架"上比（复用 `motifCanon` 的软墨量内容框与居中重合，但先做文字区掩蔽），或直接比对 TikZ 拓扑（节点数/边数/树深/扇出）。产出一张"结构族"表：族 → 成员图 → 建议参数（族内变化的文字与数字）。
2. **参数化宏**：由样式阶段（或它起的子会话）定义 `\fig<族名>{参数表}`，逐处调用；参数尽量少（标签、颜色、方向），其余写死在宏里。

### 5.3 阶段顺序：三个方案

| 方案 | 做法 | 改动面 | 代价 |
|---|---|---|---|
| ① 图后置 | images 只做体检 + 取原件；重绘改成章节转换时可调用的工具，模板由样式包提供 | 中（image 阶段职责缩小、convert 多一个工具、checker 校验点增加） | 最省，但会话要会"看图决定画不画" |
| ② 样式前置子阶段 | 样式阶段先起子会话抽图模板，再回头改造图 | 大（pilot 依赖、样式会话变长） | 中 |
| ③ 保持现状 | 样式阶段回头改造已画的图 | 小 | 双倍成本（就是用户担心的那种） |

建议 ①：它天然没有"先画一遍再改一遍"的窗口，而且与"原生 PDF 默认不重画"同向。

## 6. 外部素材（P72）

- 目录约定：`<proj>/source/assets/<名字>`（raster 或活页 PDF/TikZ 片段），md 占位符可绑定到它；
- 优先级：**素材 > 原件 > 重绘**；素材是否再矢量化是独立开关（`latex.figure_mode` 之外的 `assets_redraw`）；
- 登记：按内容哈希进 `progress_items`（不进模型请求），重跑时按哈希复用，不重复上传/转换。

---

## 7. 语义调控与定点返工（P73）

- **作用域**：`stage` / `chapter` / `figure` / `block` 四级，做成请求字段（复用 P53 的排队 + P54 的"插一条 user 消息"）；
- 每级都要有"可校验的作用域边界"：章 = 现有 `base`；图 = `progress_items` 的 key；块 = `style_fix` 的 block 名；
- 幂等：同一作用域重复下发只跑一次（沿用 `retryq` 的"重跑只补齐未完成项"语义）；
- 人话指令落成字段而不是靠"整阶段重跑"：`{"scope":"figure","key":"…","instruction":"…"}`。

---

## 8. 领导会话（P74）

要能安全指挥，先有三件确定性基础：

1. **阶段状态机**：每阶段的输入指纹、产物指纹、状态（pending/running/done/failed/stale）；
2. **事件日志**：append-only，一条事件一个作用域动作（现有 `work/sessions/*.jsonl` 是会话级，没有阶段级）；
3. **审批通道**：危险动作（清目录、重跑全书、覆盖通过过的产物）必须人工确认。

能做：按指令起停某阶段、定位失败、重派作用域、注入提示词、插话打断。
不能做：替代确定性账目（尝试号、通过记号、重试队列、幂等）——那些必须留在代码里，否则一个"能删目录的聊天框"就是新的故障源。

## 9. 样式与原书的对比（P75）

优先确定性测量，视觉只兜底：

- `pdftohtml -xml` 给出每个文本块的 bbox → 可算基线、行距、字号、页边距、栏宽；
- 同一页的原书 vs 成品按同一尺度对齐，产出差异表（行距 mm、字号 pt、边距 mm、图幅 mm）；
- 容差按印刷标准给（如行距 ±0.3mm、字号 ±0.2pt），超标才让样式会话修；
- 视觉 overlay 只用于"数值看着对但明显不对"的兜底，不做主判据。

## 10. 会话底座迁移（P76）

分层：**流程 + 账目 + 校验**（我们的价值） vs **会话执行**（转录/压缩/回放/沙箱/工具注册，通用能力）。

- 现在做：把会话执行抽成接口（`go/internal/session` 已经是边界），先迁 **img2text**（独立、无流水线账目）；
- 之后：章节转换/核对迁到 dsh / Pi-ai，流水线只保留调度与校验；
- 最后：把流水线包成 dsh 插件/skill，WebUI 用 dsh 的（或把现有 v2 页当一个视图嵌进去）；Go CLI 保留"无 UI 高分发"这一面（跑书、CI、批量）；
- 别做：正在跑书的时候换底座。

---

## 11. 明确不做（反模式）

1. 整本书一个"是否扫描"的结论——半扫描/混合导出极常见，实测第二类就是反例。
2. 每页开一次会话判类型——几百页的成本与不稳定性都不可接受。
3. "先重画再比对再裁切"——原页裁切本身就是 100% 保真，多这一步只增加成本。
4. 把尝试号/通过记号/重试队列的权威交给会话层。
5. 为了统一而把已经通过的书整本重排。
6. 把"结构相似"直接当"内容等价"——模板族要保留每个成员自己的文字与数据。

## 12. 路线（可分段验收）

| 阶段 | 范围 | 验收 | 回退点 |
|---|---|---|---|
| 0 | 判定层：`pdfimages`/`pdffonts`/`pdftotext` 体检 + `pages.json` + `progress_items.origin` | 三类样例判定正确率 ≥95%，模糊页 <10% | 纯新增，删字段即回退 |
| 1 | 三档取图：crop / extract 两条零 token 路径 + checker 校验 | 原生 PDF 跑通 images → chapters，图 100% 来自原件 | `figure_action` 强制 `redraw` 即回现状 |
| 2 | 结构聚类 + 参数化宏 + 顺序方案 ① | 模板族覆盖 ≥70% 的重复图，作图会话次数下降 ≥50% | 关掉模板开关回到逐张重绘 |
| 3 | 作用域化指令 + 定点返工 | 单图/单块返工不触发整章重转 | 保留章级重试入口 |
| 4 | 领导会话（阶段状态机 + 事件日志 + 审批） | 能在不改动产物的情况下定位并重派任一阶段 | 阶段状态机可只读 |
| 5 | 底座迁移（img2text 先行） | img2text 全链路在 dsh/Pi-ai 上等价 | 保留 Go 实现双跑 |

## 13. 需要你决策的开放问题

1. 原生 PDF 的**默认档位**：默认"取原件"（更保真、零成本），还是默认"重绘"（可编辑、可套模板）？
2. 裁切进来的图**要不要可编辑**：100% 保真但不可改字；要可改就得走重绘或 content stream 改造。
3. 模板归属：写在样式包（`\fig<族>` 与书级配色一致），还是独立 `figures.sty`（更好复用、跨书共享）？
4. `classify` 是否保留：原生 PDF 上它可能只剩"要不要重画"一个判断，是否合并进 audit 的模糊页处理？
5. 底座切换时机：先做判定层 + 三档取图（不碰会话层），还是先迁 img2text 验证底座？
