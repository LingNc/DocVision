## 三、章节树的「世代」：切历史尝试时子行跟着换（T235，补充上文第一节）

同一个父章节可以有好几条历史尝试，其中被作废的那条只把**工作树**搬进 `work/attempts/<章>/try<N>/`，它自己的转录仍留在 `work/sessions/` 或节点目录下——于是"这条转录是不是归档的"这一个布尔量分不出 `try1` 与 `try2`（两条都可能不归档，或者一条归档、另一条也归档）。只看这个布尔量的老实现有个后果：在侧栏点父行的两条历史尝试，父行换、子行不换，用户看到的是"切了没反应"。

现在世代从**路径**里读：`sessionGeneration(s)` 把 `/work/attempts/<章>/tryN/` 里的 `tryN` 抬成键 `<项目根>|<章>|tryN`（没有这一段时返回空串），`genRoot(s)` 给出项目根，`buildChapterTree` 先扫一遍全量转录收齐"哪些（章, 号）真的在归档里"，再由 `childGeneration(convert, converts, parentGen, archiveGens)` 决定这一次该取哪一代：父行自己归档就取它自己的键；否则取 live 那一代。`resolve(node, parentGen)` 把这个世代一路传给子节点、修复行与复盘行，`convertInGeneration` 在同一归档面里先精确匹配世代键、找不到才退回最新那一份（T214 的兜底不变）。

同批修的还有两处：`sessionview` 的归档判据改成前缀与路径中段都认（多项目布局下 `rel` 是 `<项目名>/work/attempts/…`，以前前缀永不命中，接口里 `archived` 恒为 false，页面的「归档」标记与活体优先整套失效）；子节点转换失败的终态改写在**这一次实际用的**那条转录上（以前配置按值传，终态会落到第 1 次尝试的历史转录末尾，页面按最新挑行，于是把早就通过的那一代显示成「会话错误」）。三条都有回归测试：`tests/chapter-tree.spec.ts` 的「T235 子行跟着父行选中的那次尝试」、`internal/sessionview/sessionview_test.go` 的多项目归档用例、`internal/latex/t235_child_transcript_test.go`。
