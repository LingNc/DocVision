# 会话基础设施、虚拟工作区与 img2text（细则）

> 本文件是 `AGENTS.md` 的**细则卫星**（T227 拆分）：三条内容由 `AGENTS.md` 的「AI 会话基础设施」「虚拟工作区」「img2text 只出 Mermaid」**逐字搬迁**而来，没有重写。看项目现状先读 `AGENTS.md`。

## 一、AI 会话基础设施（`go/internal/session`）

- **AI 会话基础设施** `go/internal/session`：可分离工具、上下文窗口、JSONL 转录（append-only；每行带 `ts` 时间戳，每次 API 请求追加一条 **`t="usage"` 用量行**（token/缓存/耗时/首字延迟/`kind`；费用按会话开始时冻进转录的 `t=meta kind=price` 费率快照算、按模型分桶，旧转录无冻结行才退回当下配置，T101），`t=meta` 与 `t=usage` 只记录**永不回放**；续跑只回放最后一次压缩检查点之后；**流式快照 sidecar `<转录>.partial`（P7）**——流式回调 ~150ms 节流原子覆写当前消息累积文本（尾 16KB），完整消息落盘/Close 即删，预览服务跨进程读它展示实时输出）、**每轮内容哈希与会话指纹（P10）**——msg 行带 `h`（12 hex 内容哈希，报障可 grep 定位；工具卡尾部 `h=…`、轨迹展开区「轮次哈希」展示），详情栏「会话哈希」是转录文件内容指纹；**续跑语义（T28/T29）**——恢复时进度计数/已用时间从转录历史继续、已 submit 的重放收账直接完成（`latex/resume.go` replaySubmit）、续跑一律原样续行不插新 user 内容（`session.Run` 空参；未提交由提醒机制兜底，T100）、悬空调用合成占位回执保证 wire 合法、**回放清洗（T159）**——坏 JSON 工具参数按 `{}` 重放并改写该回执、空正文且无工具调用的消息丢弃（只改内存历史，磁盘转录一字不动；否则坏回放会让续跑第一个请求永远 400）、回放只从最近压缩检查点开始；**输出预算兜底（T159）**——`max_tokens` 是「思考 + 正文」的总预算，开着思考的模型配得小会把预算全花在思考上、正文为空：被截断且无正文时重试翻倍（受窗口约束）并告警，会话创建时预算 <16384 也按「模型 + 预算」去重告警一次（推荐 ≥32768）；续跑开头列「已完成 X / Y，只跑剩余阶段」摘要；**终端进度行结束即定格保留**（`livePhaseRowAt` 的 fin 把 `[type] 轮次 N · 工具调用 M · 已用 Xs` 留在滚动区，新流程另起行）——`PrintConsole` 不做 quiet 门禁（它全是"必须显示"的行，quiet 只压 `Log()` 明细））、**正文残片清洗（T30/T32/T34）**——模型把不属于正文的东西写进 content 时（原始 `<parameter=…></tool_call>` 工具调用文本、`<thinking>…</thinking>` 思考泄漏；真实调用/思考已走各自通道正常执行），`StripLeakedToolXML`/`MoveLeakedThinking` 落盘/进历史前剥掉（后者移到 ReasoningContent，UI 渲染成可折叠思考块），旧转录由预览页折叠成「XML 协议残片」/「原始思考」块，名称右侧带琥珀徽标与正常思考块区分）；**两级压缩**（先零成本本地裁剪、再 AI 摘要；阈值检查在**每次请求之前**，阈值取「本地估算 / 标定估算 / 厂商实测 `prompt_tokens`」三者最大）、**输出预算随输入让路**（T123：窗口是 `prompt+max_tokens` 之和，每轮按「窗口 − 当前上下文 − 2% 余量」压 `max_tokens`，装得下就不动；曾经 262144 窗口配 131072 输出预算，prompt 涨到 13 万后那一轮直接 HTTP 400 终止会话，整桶 336 张核验白跑）、工具轮次软限制、前缀缓存亲和（稳定 `user` + `[cache-probe]`）、**submit 终态回执（T92）**——`ToolResult.Terminal`：收账成功即结束会话（不等模型收尾空转），章节划分/转换/作图/核对/mermaid 修复全走它，样式包例外（提交后还要 test-compile）、**必须显式 submit（T94）**——所有会话提前收尾未提交就同会话提醒续跑最多两次、仍不提交判失败（不再有"编译通过即采纳"的静默兜底；T227：上一次提醒只换来一字不差的答复时不再发第二次，答复变了的照发），跑歪的转换转录（工具回执里出现「未知挂载点 "source"」、或同一 N 的对照拒绝重复出现）在续跑前由 `latex/repair.go` 截到最早证据之前、另开一次尝试，源转录不动、**会话结局落盘（T99）**——每次 Run 结束写 `t=meta kind=run_end`（ok/error+原因），会话为什么停留在转录里，`latex.keep_session_records` 默认开。**运行期内存自证（T158/T162）**——SIGKILL 捕获不到，`RunBook` 启动打 `[mem]` 基线（`VmRSS`/`VmHWM` 峰值 + `MemAvailable`/`MemTotal` + swap 用量）、**前 3 分钟每 10s 采样**（续跑要同时恢复十几条会话、每条都把转录里的图片重新读成 data URL，这是启动阶段的内存尖峰）、之后每 60s 一次，收尾再打一行；**每一行同时追加到项目内的 `<proj>/work/mem.log`**（终端被刷掉/窗口关掉/进程被杀，这个文件还在，事后直接看最后几行）。可用内存 <1GiB 或 <10% 告警、<256MiB 或 <3% 明说"随时可能被 OOM 杀掉"，swap 已用 >60% 且 >1GiB 时额外提醒"实际余量比这个数字更小"（现场排查「已杀死」先看这几行，`MemFree` 不可作判据）；恢复会话的日志行带**该历史回放的图片张数与字节数**（`session.ReplayWeight`，单条 ≥32MiB 再单独告警），能直接指认是哪条会话吃内存；`--debug`/`--trace` 的启动提示写明日志文件路径（`logger.Path()`）。

## 二、虚拟工作区与挂载表

- **虚拟工作区**：每会话一张挂载表（`Runner.sessionMounts` 是唯一来源），`work:`（可写：逐章转换/修复会话是临时工作区 `work/temp/conv_<章>/work`；P34 递归节点在对应父工作区 `_subdivision/` 再按实际下发模型名给同时在途的会话数封顶，转换与核对落到同一模型时共用该额度，启动日志打并发账目并在池子之和超上限时点名告警）；父节点等待子树时释放槽位，预览按完整章节 ID 将 convert 与对应 checker 组成递归树，并显示 queued/running/waiting_children/checking_result/pass/issues/error，文案按角色分叉（T178：转换跑完=「转换完成待核对」、核对跑完=「核对完成待处理」、转换在 queued `chapterActivityLabel`）（T170：章节树一行代表"这一章现在的样子"，默认取最新一次；**T175：历史切换只钉住正在看的那一条**——`buildChapterTree(items, pinId)` 默认每个节点各取自己最新一次，只有你正在查看的那条会话所在行跟着切，同一行的另一种角色（convert ↔ checker）只取同一轮，那一轮还没核对就不显示（T187：核对号小于转换号的一律不显示，切到历史里那一次才看得到），子会话与其它章节不受影响（T193：**行头永远是转换会话**——重核只作子行，不再把 `node.convert` 置空），行上不写「第 N 次」；旧实现按列表顺序后者覆盖前者，而列表新→旧，结果停在被作废的第 1 次；T171：活动标记停在 `running` 但转录里已有 `run_end` 的折成「已中断」并排除 live，不再和真正在跑的那次并排显示「运行中」；T161：展开状态是**每个节点自己的记忆**——键 `chapter:<项目>/<阶段>/<节点ID>`，落 `state.collapsed`；点左侧展开按钮只切展开、不选中，行本身点一下只选中，两件事各一次点击就完成；手动拉开的分支一直开着，切会话/轮询都不会把别处的树收回去，没碰过的分支只在装着当前会话时自动露出）；未完成 checker 续跑使用当前 checker 模型配置并恢复原转录历史；子节点及细分父节点 checker 必须明确 ## 三、img2text 只出 Mermaid，失败可诊断

- **img2text 只出 Mermaid，失败可诊断**：提示词类型枚举 = Mermaid / Markdown table / LaTeX **公式** / 结构化文本 / 代码块 / 图表描述，`ForbidMention`（tikz/pgfplots/latex code block/latex vector）+ 第 5 条守护测试钉住；模型若回绘图代码块按**无效响应**处理（跳过、下轮重试），嵌入不认这种块，矢量图重画归**档位1 作图会话**（`internal/latex/tikz.go`）。`analyze` 把**警告**（输出有偏离但已被程序纠正、结果仍可用，T36：成功且期间有 `[WARNING]` 行）与**失败**（无产出；含 mermaid_invalid/invalid_format/empty_response 的"跳过、下轮重试"，标 `失败（跳过、下轮重试）`）在报告与 CSV 状态列分列；**首次校验失败即升级**（T37，`tools.mermaid.fix_attempts` 默认未写/`-1`；`0`=无限就地修复受安全上限保护，`N>0`=N 轮就地后再升级）进**升级修复会话**（`tools.mermaid.session_rounds/session_errors/fallback_model`，默认 32/3/空——T52 起 32）：虚拟工作区 `progress_items/mermaid_fix/<图>/` 里编辑 submit.md（write_file/**edit_file**/grep/view_image/submit 五工具，T52；多次运行的转录自动轮转 prevN 不混排），submit 过 mmdc 检查即可，编译错误累计到上限**或会话本身失败（含厂商退化空响应——finish=length/0 completion/全空，会话层重发一次自救，T50）**即清上下文切备选模型（未配置可解析 fallback_model 时不进备选段），`analyze` 报告触发统计；`preview.img2text: true`（配置 v11）时升级修复会话按书分组、编号、可搜索进会话预览；P18 起预览页有 **LaTeX/img2text 板块切换**（侧栏顶部），img2text 板块顶部是每书进度概览（done/fixed/escalated/pending 四态，从 progress_items 树推导，API `/api/img2text-progress`），`preview.img2text_all`（**默认 true**，可关）控制逐图分析转录记录（`progress_items/sessions/<md>/`）；校验日志按**实际校验对象**命名并带图片路径，错误详情**抽真错误行**（排除版本横幅，抽不到退回**最后** N 行），无效响应附**截断原文 + 总字符数**与期望格式。
