# dedupe 术语与判据（讨论用）

本文只定义 dedupe（图片相似合并）里的词和数，方便讨论时说同一个东西。**从扫描到落盘的完整流程与判定算法**见 [dedupe-algorithm.md](dedupe-algorithm.md)，档位1 其余阶段见 [latex.md](latex.md)，历史原因见 [issue.md](issue.md)。

## 对象

- **引用（ref）**：md 里的一次图片引用，一条 `![](images/书/文件名)`。该书 388 条。
- **内容 / 份**：按文件字节 `sha256` 去重后的东西。同一条内容可能被引用很多次（复制出来的同名字不同）。该书 388 引用 → 130 份。
- **副本**：内容相同的其余引用。它们不进会话、不重画，结论跟随代表图。
- **候选池**：本次要核验的“份”的集合（已分类的图）。
- **桶（bucket）**：本地相似度给出的初始候选集合，只是会话的起点，模型可以拆/并。
- **组 / 分组**：最终认为“同一枚图”的若干份。每组有且只有一个**代表图**。
- **代表图（key）**：组里唯一会被重画的那张；组内其余位置复用它产出的 LaTeX，原图 LINK 保留。
- **独立**：没有进任何组的份，自己画自己。

## 判据（数）

- **重合度 / 居中重合（align）**：把两张图的**前景内容框**按内容框居中贴进 S×S 软墨量画布（S = 这一对里较大的内容框长边，夹在 24–512；**不缩放**、**不二值化**，格值 = 格内平均软墨量 `1−通道/255`），允许平移 ±`latex.dedupe_align_shift`·S（默认 0.10·S）搜一遍（0 级在整段预算里找，之后每一级以上一层选中的格 ×2 为中心、只搜 ±2 格，**不扩窗**，T143）；网格 `G` 从 32 逐级翻倍到放得进 S 的最细一级（`latex.dedupe_align_grid` 可写固定格数或 `0.95S` 这种比例，表示**最细一级**的格数），粗层只负责把平移搜到位，**判定分取最终（最细）那一级的 Σmin/Σmax**。0–1，越大越像。
- **内容框**：软墨量 `>0.2` 的外接矩形；只用它定位贴图，所以画布上的位置/留白不影响比较（尺寸差**不**归一化，跨尺寸交给会话挂靠）。
- **中心（medoid）**：一个连通片里“与其余成员平均重合度最高”的那张。它只是选代表图的中间量。
- **典型成员**：与中心重合 ≥ 0.95 的成员。
- **代表图规则**：典型成员里**内容框最大**那张（既典型又最全）；没有典型成员时用中心自己。
- **阈值**（三个，含义不同）：
  - `latex.dedupe_align_min`（默认 0.60）：**能不能进同一组**的门槛——成员对组代表图的重合度。
  - `latex.dedupe_icon_auto`（默认 0.75，0=关闭）：**本地直接定组、不进会话**的门槛（只对内容框 ≤ 20000 px² 的小图生效）。
  - `latex.dedupe_align_shift`（默认 0.10）：允许的平移量。
- **复核**：代表图 != 中心，所以“对中心的数”不等于“对代表图的数”；成员必须对**代表图**再算一次 ≥ 阈值才能进组，否则悄悄掺进一张 0.71 的图而名义门槛是 0.75。唯一例外（T152）：对代表图不够、但对组内**某个已经达标的成员**仍 ≥ `dedupe_align_min` 的，随组带入——同一枚图换分辨率/长宽比时与中心的分数会明显偏低，会话已逐张确认过是同一张图，不该在这个口径上被拆掉；只比一轮、不拿带入的成员当跳板，带入的也不当代表图。所以组内最低分可能低于门槛，`report.md` 会加脚注、`review.html` 会把每个成员都摊开，别把这当成判据漂移。
- **组类别**：组内占比最大的 `class`（vector/raster/text）。class **不参与合并判定**，只决定中心图按哪一类处理：多数为 vector 就把中心图重画一次、组内其余位置复用它的成品，否则保留原图（T147；T134 只把它用在自动定组上，会话复核处一直留着“多数非 vector 就只合并 vector 成员”的旧分支）。

## 环节

- **自动定组**：本地按 `dedupe_icon_auto` 直接连成组并选好代表图，**不开会话**。
- **核验会话**：模型逐张看原图（`compare_images` 并排图也算看过），提出分组并选 key；提交后 runner 用上面的重合度判据逐成员复核。
- **整理会话**：只把“没进桶的未分配图”和各组代表图摆一起，补归位。
- **挂靠（attached）**：后期把 0.60–0.75 的图并进**已确认组**，代表图不变（T135）。
- **并查集收口**：会话结束后，任何仍独立的份只要对某个已确认组的代表图 ≥ `dedupe_align_min` 就挂进去，保证“0.6 以上连通 → 一个组”（T135）。
- **组间收口（folded）**：自动定组只是“这几张不用再看”，不是一个桶就该有十几个组——同一个桶内、关键图互相达标的组在最后折成一组，代表图按“典型（≥ `dedupe_align_typical`）且内容框最大”重挑，成员按各块已确认的结论原样收编（不拿新中心重闸一遍，否则同一枚图还是会被拆回好几份）。跨桶不折（T149）。

## 落盘

- `source/progress_items/<md>/<img>.json`：每份的状态与 `equivalent_to`（真源）。
- `source/dedupe/groups.json`：最终分组（组、代表图、成员、对代表图的重合度、类别、`source`＝auto/session/attached/folded、副本）+ 输入与规则指纹。
- `source/dedupe/report.md`：一页汇总，代表图与独立图是相对链接（点开就是原图）。
- `source/dedupe/review.html`：**看图页**（T150/T154）——每组一张卡片，代表图标 `★`、成员按 `groups.json` 的顺序排成缩略图网格，缩略图宽 160px、是 `thumbs/<内容哈希前 12 位>.jpg` 的**文件链接**（不再内嵌 base64），分组默认收起、可一键展开，点缩略图在页内灯箱里看大图（缩放/平移/再点一下关闭）。同一个文件既能离线双击，也能从会话预览页的「复查」入口直接打开（`/dedupe?project=<项目名>`，见 [sessions.md](sessions.md)）。分组到底对不对，直接看这一页。
- `source/dedupe/scan.json`：**扫描中间量缓存**（T153）——分桶结果与逐对明细（分数/判定层/画布/级数/平移），键是「版本 + 判定相关配置 + 排序去重后的内容哈希集」。同一批图续跑时键命中就跳过桶扫描与逐对打分（~7.0s → ~1.3s），产物与不缓存时逐字节相同；键对不上照常重算并覆写。

## 中间量落盘（T136）

`<proj>/source/dedupe/metrics/`：

- `pairs.csv`：逐对一行 —— `feature_similar`（最初那套逐对相似度判据，0/1）、`align`（居中重合度，0–1，拿不到覆盖率留空）、`align_level`/`canvas`/`levels`/`shift_y`/`shift_x`（判定层格数、画布边长、一共搜了几级、判定层上搜到的平移格数）、`skip`（没走这条判据的原因：`no_content_box`/`too_large`/`prefilter`/`pair_cap`，空 = 算出了分数）、`same_bucket`（最终是否同桶）。份数是平方关系：该书 130 份 ≈ 8385 行。
- `buckets.json`：桶 → 成员、未分配份、逐字节副本数。

注意两套判据都在用，别再混着说（也答了「最初那个相似度分组还在不在」）：

1. **初始相似度分组**（`motifFeatureSetSimilar`，逐对 0/1 判据，含像素指纹/形状/主色）——一直存在，就是“最初算的那个”；
2. **居中重合归并**（T130，`align ≥ dedupe_align_min`）——在 1 的基础上**并进桶**，所以**桶 = 1 ∪ 2**（`FindVisualMotifCandidatesAligned`）。

## 扫描成本（T140）

逐对相似度与居中重合度都是**分桶之前**的一次全池扫描（桶是并查集的结果，不是扫描的边界）——重合度若只在相似度桶内算，就补不回被逐对相似度切开的那半边（T130 的动机）。代价是 O(小图标数²)，于是有两条不改变判据的省法：

1. **逐字节副本只算一份**：该书 388 条引用只有 130 份不同内容，`rgbaFingerprint` 相同的图只留代表参与扫描（副本已被指纹并进代表所在的桶）；
2. **并行算判定、串行做 union**：达标与否是纯函数，按 CPU 并行（≤8）算，再按原顺序并查集——合并顺序不变，分组逐字一致；已在同一桶里的对直接跳过。

实测该书 388 引用：覆盖率 191ms、逐对相似度 0.30s、重合度扫描 **104s → 3.5s**（16 核开发机，用户机 30s → ≈3s），分组与合并数不变。单对 ~1.9ms 里大部分是"解顶到窗口边缘就翻倍重搜"（0 级 49 次 → 平均 314 次重叠度计算）。那层扩窗本来就不在约定的判据里（T143 按用户口径删掉：细层只在上层选中的格子 ±2 格里找、每级单次扫描），删掉后扫描 **3.5s → 2.3s**；对 7503 对可算分数的对：7458 对分数变化（最大降幅 0.416）、40 对跌破 0.60、**跌破 0.75 的 0 对**，桶 `[102,2]` → `[100,2]`，自动组逐组不变。

## 为什么画布是 S 自适应、而格子逐级翻倍

`S` 按**每一对**算（`clamp(max(a.内容框长边, b.内容框长边), 24, 512)`），不能是常量：换一本书，图标可能 32px 也可能 70px，常量画布会让同一枚图在另一种尺子上失真；也不按池子取 P90——同一池子里混着 28×38 小图标和整页截图时，P90 会让小图标在画布里只占一角、重合度被系统性压低（T145 按代码事实统一口径）。内容框**居中贴进 S×S 且不缩放**——已验证逐级搜索的最佳平移全程是 `(0,0)`，说明居中是对的；代价是**尺寸差一倍的同图不再自动合并**（实测缩到 0.6× 掉到 0.22），这类跨尺寸交给会话挂靠（`dedupe_attach_min`）。

网格 `G` 从 32 起逐级翻倍，一直做到放得进 S 的最细一级；粗层只用来把平移搜到位，**判定分只看最细那一级**（用户定：「判定层就是逐级搜索的最终结果，不要固定一个 G=多少的层」）。只差一个符号的图在粗网格上会被误并（内容框 171×390 的交换图：G=32 时 0.765、G=256 时 0.373），所以“细层定分”不是性能优化，是正确性前提。

只对**内容框 ≤200×200 px 的小图标**（`latex.dedupe_icon_max_area`，默认 200000 px²）生效，更大的图仍走逐对相似度；`pairs.csv` 的 `skip` 列会标出没走这条判据的对（`too_large`/`no_content_box`，另外 `prefilter`/`pair_cap` 是省时间的跳过，T151）。
